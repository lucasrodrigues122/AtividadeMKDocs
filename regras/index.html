    Regras e Fluxos

    ℹ️ Categoria: 02_Arquitetura_SAD (Documento de Arquitetura de Software)
    Projeto: JURISYNC - Sistema de Gestão para Escritório de Advocacia
    Módulo: Autenticação, Segurança e Gestão de Casos
    Tecnologias: Java 17, Spring Boot, Spring Security, PostgreSQL, JPA/Hibernate
    Status: IMPLEMENTADO

    Visão Geral do Componente

    Módulo responsável pela autenticação dos advogados e pelo gerenciamento dos processos jurídicos no PostgreSQL. O Spring Security gerencia sessões via cookies e impõe controle de acesso, garantindo o isolamento de dados para que cada usuário visualize apenas os seus casos.

    Fluxo de autenticação de acesso:

    sequenceDiagram
    autonumber
    actor Advogado as Advogado (Browser)
    participant SS as Spring Security
    participant CC as CasoController
    participant CR as CasoRepositorio
    participant DB as PostgreSQL

    box Yellow 1. Autenticação
    Advogado->>SS: POST /login (email, senha)
    SS->>DB: Busca usuário e valida hash BCrypt
    DB-->>SS: Usuário válido
    SS-->>Advogado: 200 OK + Cookie de Sessão
    end

    box Yellow 2. Acesso aos Dados Isolados
    Advogado->>SS: GET /casos (envia Cookie)
    alt Sessão Inválida ou Ausente
        SS-->>Advogado: 401 Unauthorized / Redireciona /login.html
    else Sessão Válida
        SS->>CC: Encaminha requisição + Usuário Logado
        CC->>CR: findByUsuario(usuarioLogado)
        CR->>DB: SELECT * FROM tb_casos WHERE usuario_id = ?
        DB-->>CR: Lista de casos do usuário
        CR-->>CC: List<Caso>
        CC-->>Advogado: 200 OK (Lista de Casos)
    end
    end

    Modelo de Banco de Dados (PostgreSQL)

    Relacionamento: tb_usuarios (1) —— (N) tb_casos (Um usuário possui vários casos e cada caso pertence a um único usuário).

    Tabela: tb_usuarios (Entidade: Usuario)

    Armazena as credenciais e dados dos advogados.

    Coluna Tipo SQL Chave / Restrição Descrição
    id BIGINT PRIMARY KEY Identificador único
    nome VARCHAR(255) NOT NULL Nome completo
    email VARCHAR(255) UNIQUE, NOT NULL E-mail de login
    senha VARCHAR(255) NOT NULL Hash da senha (BCrypt)

    Tabela: tb_casos (Entidade: Caso)

    Armazena os processos jurídicos cadastrados.

    Coluna Tipo SQL Chave / Restrição Descrição
    id BIGINT PRIMARY KEY Identificador do caso
    numero_processo VARCHAR(100) NOT NULL Número do processo
    titulo VARCHAR(255) NOT NULL Título legível
    descricao TEXT Opcional Detalhes do caso
    usuario_id BIGINT FOREIGN KEY Referência a tb_usuarios(id)

    Mapeamento das APIs / Endpoints:

    Método Endpoint Acesso Descrição
    GET /login.html Público Exibe a página de login
    POST /login Público Valida credenciais e inicia sessão
    GET /cadastro.html Público Exibe formulário de cadastro
    POST /cadastrar Público Registra novo usuário (criptografa senha com BCrypt)
    GET /casos Autenticado Lista os processos do usuário logado
    POST /logout Autenticado Encerra a sessão ativa

    Trechos de código principais:

    Relacionamento JPA na Entidade (Caso.java):

    @Entity
@Table(name = "tb_casos")
public class Caso {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank
    private String numeroProcesso;

    private String titulo;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "usuario_id", nullable = false)
    private Usuario usuario;

    // Getters e Setters
}

    Consulta Filtrada no Repositório (CasoRepositorio.java):

    public interface CasoRepositorio extends JpaRepository<Caso, Long> {

    /**
     * Busca apenas os processos pertencentes ao usuário informado (garante isolamento).
     */
    List<Caso> findByUsuario(Usuario usuario);
}

    Regras de Segurança

    • Criptografia de Senhas: Nenhuma senha é armazenada em texto puro. O UsuarioServico utiliza BCryptPasswordEncoder para aplicar hash antes da gravação.
    • Proteção de Rotas: O Spring Security bloqueia requisições não autenticadas para rotas protegidas (/casos, /logout), redirecionando-as para o login.
